# Chat App

Веб-приложение для личного общения в реальном времени. Пользователи могут авторизоваться через Google, добавлять друг друга в друзья и обмениваться сообщениями.

Проект создан в образовательных целях, чтобы попрактиковаться в разработке full-stack-приложения на Next.js, работе с Redis, OAuth-аутентификацией и real-time-событиями.

## Возможности

- Авторизация через Google.
- Просмотр списка друзей.
- Отправка и обработка заявок в друзья.
- Личные чаты между пользователями.
- Отправка сообщений с обновлением интерфейса в реальном времени.
- Хранение пользователей, связей между ними и истории сообщений в Redis.
- Адаптивный интерфейс для настольных и мобильных устройств.

## Архитектура

Приложение использует монолитную full-stack-архитектуру на Next.js. Пользовательский интерфейс, серверная логика и API находятся в одном проекте. Отдельные инфраструктурные сервисы отвечают за хранение данных, аутентификацию и передачу real-time-событий.

```text
┌─────────────────────────────┐
│        Web Browser          │
│                             │
│    React UI + Pusher JS     │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│          Next.js            │
│                             │
│  App Router                 │
│  Server Components          │
│  API Route Handlers         │
│  NextAuth.js                │
└──────────┬──────────┬───────┘
           │          │
           ▼          ▼
┌────────────────┐  ┌────────────────┐
│  Upstash Redis │  │     Pusher     │
│                │  │                │
│ Пользователи   │  │ Real-time      │
│ Друзья         │  │ события        │
│ Сообщения      │  │                │
│ Сессии/данные  │  └────────────────┘
└────────────────┘
```

### Как работает отправка сообщения

1. Пользователь вводит сообщение в чате.
2. Клиент отправляет запрос на `POST /api/message/send`.
3. Сервер проверяет сессию пользователя и доступ к чату.
4. Сервер проверяет, что собеседник находится в списке друзей.
5. Создаётся сообщение с уникальным идентификатором и временной меткой.
6. Через Pusher отправляются события для обновления открытого чата и уведомления собеседника.
7. Сообщение сохраняется в Redis.

Pusher используется для доставки событий в реальном времени, а Redis — для хранения истории сообщений. Это разные задачи, поэтому сервисы дополняют друг друга.

> Примечание: в текущей реализации события Pusher отправляются до завершения сохранения сообщения в Redis. Это стоит учитывать при обработке ошибок и возможных повторных запросов.

### Основные директории

- `src/app` — страницы, layout-компоненты и серверные API-обработчики Next.js.
- `src/app/api` — обработчики HTTP-запросов для операций с друзьями и сообщениями.
- `src/components` — переиспользуемые React-компоненты.
- `src/helpers` — вспомогательные функции, в том числе чтение данных из Redis.
- `src/lib` — конфигурация сервисов, аутентификация, работа с Redis, Pusher и схемы валидации.

## Локальный запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/Chevalierus/chat-app-next-ts.git
cd chat-app-next-ts
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Настройка переменных окружения

Создай файл `.env.local` в корне проекта.

```dotenv
# Google OAuth
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=

# NextAuth
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=

# Upstash Redis
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=

# Pusher
PUSHER_APP_ID=
NEXT_PUBLIC_PUSHER_APP_KEY=
PUSHER_APP_SECRET=
```

Заполни значения данными из соответствующих сервисов. `NEXTAUTH_SECRET` должен быть случайным секретным значением.

Переменные `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` создаются в настройках OAuth-клиента Google. Для локального запуска необходимо зарегистрировать подходящие адреса перенаправления в настройках OAuth.

Redis URL и токен берутся из настроек Upstash Redis. Идентификатор приложения, ключ и секрет Pusher — из настроек приложения Pusher Channels.

Не публикуй `.env.local` и не добавляй секреты в Git.

### 4. Запуск в режиме разработки

```bash
npm run dev
```

Открой в браузере `http://localhost:3000`.

### 5. Проверка сборки

```bash
npm run lint
npm run build
```

Для запуска production-сборки локально:

```bash
npm run start
```

Перед этим необходимо выполнить `npm run build`.

## API

Основные API-эндпоинты:

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `POST` | `/api/friends/add` | Отправить заявку в друзья |
| `POST` | `/api/friends/accept` | Принять заявку в друзья |
| `POST` | `/api/friends/deny` | Отклонить заявку в друзья |
| `POST` | `/api/message/send` | Отправить сообщение в чат |

## Хранение данных

Redis используется как хранилище ключей и структур данных.

Основные шаблоны ключей, встречающиеся в коде:

| Ключ | Назначение |
|---|---|
| `user:<userId>` | Данные пользователя |
| `user:email:<email>` | Поиск идентификатора пользователя по email |
| `user:<userId>:friends` | Множество идентификаторов друзей |
| `user:<userId>:incoming_friends_request` | Входящие заявки в друзья |
| `chat:<chatId>:messages` | Сообщения чата, хранящиеся в отсортированном множестве |

Сообщения содержат идентификатор, идентификатор отправителя, текст и временную метку.

## Ограничения проекта

Это пет-проект, а не production-система. В текущем варианте:

- Redis одновременно используется для нескольких типов данных приложения.
- Некоторые API-обработчики возвращают ошибки в разном формате.
- Надёжность согласования между отправкой real-time-событий и сохранением данных можно улучшить.
- Автоматические тесты, мониторинг и полноценная обработка эксплуатационных ошибок требуют отдельной доработки.

Эти ограничения не мешают использовать проект для изучения технологий и демонстрации навыков full-stack-разработки.
